# TabLLM reproduction and reference library

**THIS IS A RELEASED-CODE COMPATIBILITY REPRODUCTION, NOT A BIT-EXACT REPRODUCTION OF THE HISTORICAL SOFTWARE STACK.**

`experiments/tabllm_retrospective_audit_v1/` contains the original four-arm frozen results. `experiments/tabllm_reference_space_v1/REFERENCE_MANIFEST_V1.json` is the complete 24-reference library, including the primary `ref_00`, deterministic mappings and generation logic. `scripts/run_tabllm_reference_space_v1.py` preserves dataset-specific seeds and duplicate-skipping. The summary includes both index-aligned global constructions and independent product-space sensitivity. They are different summaries and are not interchanged.

`experiments/tabllm_paired_reference_decomposition_v2/` preserves the 5,000 paired positive-weight bootstrap outputs and simultaneous 216-utility intervals. `experiments/tabllm_all_reference_k512_v1/summary_v1/` contains the exhaustive extension and all-reference decay. `experiments/tabllm_ranon_support_ladder_v1/` contains n_adapt 0/4/32/512; `experiments/tabllm_w2_fixed_mapping_v2/` contains the separate fixed-mapping feature_001 / Field A / Variable A extension. The latter has a different zero-shot anchor and 2,000 stored bootstrap replicates; do not mix its anchor with the historical one. `category_index.csv` lists every distributed file in this category.

The compatibility port is in `scripts/run_tabllm_retrospective_audit_v1.py` and `scripts/run_tabllm_published_shot_ladder_v1.py`. Exact upstream identifiers are in `asset_identifiers.json`. The released executable configuration is bigscience/T0 11B, despite a T0pp description in the original paper. Loading is performed by the preserved runner with explicit `--tabllm-root`, `--tfew-root`, `--checkpoint-source-root`, `--model-path`, and `--checkpoint` paths; inspect its --help before launch. No weights are bundled.

Recorded T-Few modifications: (1) use the pinned complete corresponding upstream `modify_model.py` because the released TabLLM tree contains only a subset; (2) use the pure-Python protobuf compatibility implementation; (3) cast newly created float32 IA3 parameters with the modified T0 model to bfloat16; (4) replace historical Lightning orchestration with the standalone PyTorch port while preserving the released objective, Adafactor settings, warmup, sampling and scoring. These exact operations remain visible in the preserved runner, not reconstructed as a fictitious upstream diff. Full change context is retained in the original `RUN_MANIFEST_V1.md` and adaptation protocols.
